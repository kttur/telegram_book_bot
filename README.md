# telegram_book_bot

Telegram-бот для поиска и загрузки книг из OPDS-каталога.

## Каталоги и переключение зеркал

Адреса задаются в `catalogs.json` — JSON-массиве базовых URL:

```json
[
  "https://flibusta.is/opds",
  "https://mirror.example/opds",
  "http://YOUR_V3_ONION_ADDRESS.onion/opds"
]
```

В примере второй и третий адреса — заглушки: замените их адресами своих
зеркал. В поставляемом файле оставлен только прежний адрес каталога.
Альтернативы должны быть зеркалами одной библиотеки с одинаковыми путями,
идентификаторами книг и порядком результатов. Это не список независимых библиотек.

При запуске бот выбирает первый адрес. Если запрос ещё не завершился через
`OPDS_SOFT_TIMEOUT` (по умолчанию 5 секунд), бот запускает следующий источник,
сохраняя предыдущую попытку. Возвращается первый полностью полученный и проверенный
результат любого из работающих источников. При сетевой ошибке, HTTP-ошибке,
некорректной ленте или файле следующий источник запускается сразу.
Рабочий адрес становится текущим для следующих запросов. Если он тоже перестал
работать, бот снова перебирает альтернативы, включая ранее недоступные.
После перезапуска перебор начинается с первого адреса; автоматического возврата
к первому зеркалу, пока текущее работает, нет.

Переключение действует для поиска, страниц, загрузки книг и обложек.
Ссылки в ранее отправленных кнопках на настроенные зеркала перенаправляются
на текущее зеркало с сохранением пути и параметров. Относительные ссылки
разрешаются относительно фактически полученной ленты. Внешние ресурсы,
чьи адреса отсутствуют в списке, загружаются без подмены домена.
Пустая корректная лента означает отсутствие результатов, а не отказ зеркала.
Если исчерпан лимит неудачных попыток, бот сообщает об этом в чате.

### Таймауты и число попыток

`OPDS_HARD_TIMEOUT` (по умолчанию 90 секунд) задаёт общий предел одной попытки:
получение cookie, соединение, перенаправления, загрузка и проверка результата.
После этого срока результат попытки не принимается. Soft timeout только запускает
альтернативу и не считается ошибкой. Значения задаются в секундах и должны
удовлетворять `0 < OPDS_SOFT_TIMEOUT < OPDS_HARD_TIMEOUT`.

`OPDS_MAX_ATTEMPTS` — максимальное число попыток **для одного ресурса**.
Если переменная не задана или пуста, лимит равен числу уникальных адресов.
При большем лимите список обходится повторно. Например, при трёх источниках
и лимите 6 порядок будет `1 → 2 → 3 → 1 → 2 → 3`, начиная с текущего зеркала.
Если очередь снова дошла до источника, чья предыдущая попытка ещё выполняется,
бот ждёт её завершения или hard timeout; повтор до этого момента не запускается.
Любая из параллельных попыток может успешно завершить операцию во время ожидания.

Каждая неудачная попытка, включая явный отказ и hard timeout, расходует лимит.
После запуска последней разрешённой попытки бот ждёт все оставшиеся результаты;
ошибка отправляется только после неудачи всех разрешённых попыток.
Победивший результат отправляется сразу, остальные попытки отменяются,
а их поздние ответы не меняют выбранное зеркало и статус. Сессии и cookie
изолированы между параллельными попытками, полученные cookie сохраняются
для следующих запросов к соответствующему зеркалу.

Пример `.env` с двумя обходами трёх источников:

```dotenv
OPDS_SOFT_TIMEOUT=5
OPDS_HARD_TIMEOUT=90
OPDS_MAX_ATTEMPTS=6
```

`OPDS_CONNECT_TIMEOUT` и `OPDS_READ_TIMEOUT` остаются сетевыми ограничениями:
ожидание соединения и отсутствие новых данных. Они могут завершить попытку раньше
hard timeout. Общий срок отдельно контролируется планировщиком: регулярное
поступление небольших порций данных не продлевает его. Requests выполняет сетевой
ввод-вывод в потоках; отменённый запрос освобождает соединение при следующем
возврате из сетевого чтения или сетевом таймауте. Отправка успешного результата
и запуск следующей попытки после hard timeout не ждут этого освобождения.
Для локального запуска обновите зависимости из `requirements.txt`:
чтение доступных данных использует `read1` в обновлённом urllib3.

Внешние ресурсы используют тот же лимит и hard timeout, но повторяется их
исходный URL: домен такого ресурса не заменяется зеркалом каталога.
После изменения `.env` пересоздайте контейнер приложения:

```sh
docker compose up -d --build app
```

После изменения `catalogs.json` перезапустите бот, например:

```sh
docker compose restart app
```

## Запуск в Docker Compose с Tor

1. Скопируйте `.env.example` в `.env` и задайте `TOKEN` и `OPENAI_API_KEY`.
   Ключ OpenAI нужен существующей функции рекомендаций и проверяется при запуске.
2. Добавьте нужные зеркала в `catalogs.json`.
3. Создайте **файл** `books.db`, если его ещё нет, чтобы Docker не создал
   вместо него каталог при монтировании:

   ```sh
   python -c "from pathlib import Path; Path('books.db').touch(exist_ok=True)"
   ```

4. Запустите сервисы:

   ```sh
   docker compose up -d --build
   ```

Compose собирает отдельный Tor-клиент из Debian-пакета `tor` и задаёт боту
`TOR_PROXY_URL=socks5h://tor:9050`. SOCKS-порт доступен внутри сети Compose;
на хост он не публикуется. Данные Tor сохраняются в volume `tor-data`.
Состояние соединения через Tor проверяет healthcheck; логи доступны командой
`docker compose logs -f tor`.

По умолчанию обычные HTTP(S)-адреса открываются напрямую, а `.onion` — через Tor.
Для всех запросов к каталогам и связанным ресурсам через Tor установите в `.env`:

```dotenv
OPDS_USE_TOR=true
```

Это относится к лентам, книгам, обложкам, внешним ресурсам и перенаправлениям.
Соединения с Telegram и OpenAI используют свои прежние настройки.
Обложки бот загружает сам и отправляет в Telegram файлом, поэтому они работают
и с onion-адресами. Недоступная обложка не мешает показать описание книги.
Для cookie и OPDS-авторизации используются отдельные сессии каждого зеркала;
`OPDS_USER`/`OPDS_PASS` не передаются внешним ресурсам.

Tor при первом запуске требует времени на подключение. Бот запускается вместе
с Tor без ожидания bootstrap, чтобы обычные зеркала могли работать сразу.
Если единственный доступный каталог — onion, дождитесь в логах Tor
`Bootstrapped 100%` и повторите запрос. Когда Tor недоступен, onion-адрес
не открывается напрямую: бот пробует остальные альтернативы.

## Статус операций

При нажатии кнопки индикатор ожидания остаётся до завершения операции или
до порога `BOT_STATUS_DELAY` (по умолчанию 8 секунд). Этот порог выбран с запасом:
Telegram не гарантирует точного срока жизни callback. Затем бот подтверждает
нажатие и отправляет отдельное сообщение в ответ на исходное сообщение с кнопкой,
например:

```text
Поиск книг: «Дюна»
Соединение с сервером 2 из 3 через Tor…
Этап: Получение каталога
Попытка 2 из 6 · одновременно: 2
```

Номер сервера соответствует позиции адреса в `catalogs.json`; отдельно показан
номер попытки и число ещё работающих запросов. Если ожидается повтор занятого
источника, статус сообщает об ожидании до hard timeout. Бот редактирует это же
сообщение при смене зеркала или этапа (cookie, каталог, книга, обложка,
отправка в Telegram), не чаще раза в секунду. Для каждой операции используется
своё сообщение с поисковой строкой, названием раздела или именем файла книги.
По завершении статус меняется на «Готово.» либо причину ошибки. Для быстрых
успешных операций отдельное сообщение не создаётся. Порог относится только
к показу статуса и не отменяет загрузку или перебор зеркал.

## Ожидание обложки

После получения описания бот ждёт обложку не дольше `COVER_WAIT_TIMEOUT`
(по умолчанию 2 секунды). Если она успела загрузиться, карточка сразу приходит
с фото. Иначе бот отправляет описание и кнопки, а загрузка продолжается в фоне.
Когда обложка готова, бот добавляет её к той же карточке через `editMessageMedia`:
ID сообщения, текст основной карточки и кнопки сохраняются. Новое сообщение
с обложкой не создаётся. Значение `0` позволяет сразу отправлять текст.

Telegram ограничивает подпись к фото 1024 символами. Поэтому основная карточка
укладывается в этот лимит, а продолжение длинного описания отправляется отдельно
и сохраняется полностью. Это ограничение учитывается также для emoji.
Подробнее: [editMessageMedia](https://core.telegram.org/bots/api#editmessagemedia)
и [InputMediaPhoto](https://core.telegram.org/bots/api#inputmediaphoto).

Порог ожидания не отменяет загрузку: обложка использует общий механизм soft/hard
таймаутов и лимит попыток. Уже полученное описание сохраняется; при смене зеркала
повторяется только запрос обложки. Книга и обложка являются отдельными ресурсами,
поэтому у каждой свой лимит. Незавершённый файл на другом зеркале скачивается
с начала: докачка по HTTP Range и объединение частичных файлов не реализованы.
После отправки описания операция считается завершённой, а обложка
добавляется независимо. Ошибка загрузки или редактирования не мешает пользоваться
карточкой. Фоновая загрузка использует отдельные сессии и cookie, чтобы новые
запросы не конкурировали за общий сетевой клиент. При перезапуске бота
незавершённые загрузки обложек не восстанавливаются.

## Локальный запуск

Проект рассчитан на Python 3.10–3.12 с текущими закреплёнными зависимостями.
Установите зависимости, экспортируйте переменные из `.env.example` в окружение
и запустите `python src/main.py`. Сам Python-код `.env` не загружает.
Для локального Tor задайте `TOR_PROXY_URL=socks5h://127.0.0.1:9050`.

Дополнительные настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPDS_CATALOGS_FILE` | `catalogs.json` в корне проекта | Путь к списку зеркал при локальном запуске; Compose монтирует его в `/app/catalogs.json` |
| `TOR_PROXY_URL` | Не задана локально | SOCKS5-прокси Tor; обязательна для onion и режима `OPDS_USE_TOR=true` |
| `OPDS_USE_TOR` | `false` | Через Tor также открывать обычные адреса ресурсов каталогов |
| `OPDS_CONNECT_TIMEOUT` | `10` | Таймаут установки соединения, секунды |
| `OPDS_READ_TIMEOUT` | `60` | Таймаут ожидания данных, секунды |
| `OPDS_SOFT_TIMEOUT` | `5` | Через сколько секунд запускать следующий источник, сохраняя предыдущую попытку |
| `OPDS_HARD_TIMEOUT` | `90` | Общий срок одной попытки, включая cookie, перенаправления, загрузку и проверку |
| `OPDS_MAX_ATTEMPTS` | Число уникальных зеркал | Лимит попыток для каждого ресурса; положительное целое число, больший лимит повторяет обход |
| `BOT_STATUS_DELAY` | `8` | Через сколько секунд переходить от индикатора кнопки к сообщению; больше 0 и не больше 10 |
| `COVER_WAIT_TIMEOUT` | `2` | Первичное ожидание обложки после получения описания, секунды; `0` — сразу отправить текст |
| `OPDS_USER`, `OPDS_PASS` | Не заданы | Общая Basic Auth для настроенных зеркал |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

Используется именно `socks5h`, чтобы DNS разрешался на стороне прокси,
как описано в [документации Requests](https://requests.readthedocs.io/en/stable/user/advanced/#socks).
Глобальные переменные прокси и `.netrc` для запросов каталогов игнорируются:
маршрут определяется настройками выше.

## Проверки

```sh
python -m unittest discover -s tests -v
```

Тесты используют подменённые сетевые ответы и локальные HTTP-серверы.
Telegram, OpenAI и публичные каталоги для них не нужны.
